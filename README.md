# Seesun Wiki

개념 문서와 업무 매뉴얼을 함께 두는 위키. 로그인한 사람은 누구나 고치고, 저장할 때마다 git 커밋이 남는다. AI 도구는 MCP 로 붙어 읽고 고친다.

서버는 Rust(`server/`), 화면은 React(`web/`)다. 2026-11-09 Node(Express) 서버에서 옮겼다 — `data/` 는 그대로 쓴다(계정 · 토큰 · 로그인 쿠키까지 이어진다).

## 실행

필요한 것 : Rust(cargo) · Node 20 이상(화면 빌드 · 명령줄 스크립트) · git

```bash
npm --prefix web install
npm run build        # 화면(web/dist)과 서버(server/target/release/seesun-wiki)를 만든다
npm start            # http://127.0.0.1:4500
```

처음 열면 계정이 없으므로 로그인 화면이 「첫 관리자 계정 만들기」로 바뀐다. 여기서 만든 계정이 관리자다.

처음 켤 때 뜻 검색 모델(EmbeddingGemma 4비트판, 약 200MB)을 Hugging Face 에서 받아 `data/models` 에 둔다. 받는 동안 · 받지 못하면 낱말 검색만 쓴다.

빈 위키에 대문과 「위키 사용법」 매뉴얼을 넣으려면 서버를 켜고 `npm run wiki -- login <계정>` 뒤 `npm run seed`.

## 구성

| 자리 | 무엇 |
|---|---|
| `server/` | Rust 서버(axum). JSON API · 그림 · MCP(`/mcp`) · 만든 화면을 한 포트에서 낸다 |
| `web/` | React + shadcn/ui 화면. `npm run build` 결과를 서버가 그대로 낸다 |
| `scripts/` | 명령줄 창구(`wiki.mjs`) · 시드 · oximemo 가져오기. 모두 서버의 MCP 를 거쳐 쓴다 |
| `data/content/` | 문서 git 저장소. `pages/` 마크다운 · `assets/` 그림 |
| `data/users.json` | 계정 · 소속 · 비밀번호 해시 · MCP 토큰 해시 |
| `data/secret` | 로그인 쿠키 서명 키. 지우면 모두 다시 로그인한다 |
| `data/settings.json` | 가입 허용 여부 · 소속 목록(`orgs`, 기본 김해본사 · 서울본부 · 대전본부 · 부산본부) |
| `data/models/` | 받은 임베딩 모델. 지우면 다음에 켤 때 다시 받는다 |
| `data/embeddings/` | 단락 벡터 캐시. 지우면 다음에 켤 때 다시 만든다(문서 수십 장이면 수십 초) |

`data/` 하나만 복사하면 위키 전체가 옮겨진다. 문서 저장소는 보통 git 저장소라 `git log` 로 그대로 볼 수 있다.

### 문서 경로 : 묶음 · 종류

경로는 `<묶음>/<종류>/<이름>` 이다. 맨 앞 폴더가 묶음, 그다음 폴더가 종류다.

묶음은 회사의 업무 분야다(`산사태` · `공통`). 여러 사업 분야가 한 위키를 쓰는데 분야마다 같은 이름의 용어가 뜻이 달라(「위기경보」 · 「대피소」), 2026-11-09 종류 앞에 묶음을 두었다.
「사업」은 끝나도 용어는 다음 사업에서 그대로 쓰므로 사업이 아니라 분야로 나눈다. 사업 하나의 매뉴얼은 묶음 안의 권으로 둔다.

- **공유 묶음** : 어느 묶음을 보든 함께 보이는 묶음(처음에는 `공통` — 여러 분야가 같은 뜻으로 쓰는 용어 · 위키 사용법). 여러 개를 둘 수 있다.
- **묶음과 권 목록** : `data/content/bundles.json`(문서와 같은 git 저장소, 바꿀 때마다 커밋). 묶음의 설명 · 공유 여부, 매뉴얼 권의 설명 · 순서를 적는다.
  편집자 누구나 화면 「묶음과 권」(`/bundles`)에서 만들고 고친다 — API `GET /api/bundles` · `POST /api/bundle` · `/api/bundle/delete` · `/api/volume` · `/api/volume/delete` · `/api/volume/order`(권 차례를 한 커밋으로 다시 매김).
  목록에 없어도 문서 경로에 나오는 묶음 · 권은 그대로 보인다. 이름은 경로의 한 칸이라 바꾸지 않고, 지우기는 문서가 하나도 없을 때만 된다.
  2026-11-10 전에 만든 위키는 서버를 켤 때 지금 묶음으로 목록을 만들고 `공통` 을 공유로 둔다(커밋 「묶음 목록을 만든다」).
- 묶음 이름으로 `개념` · `매뉴얼` · `틀` 은 쓰지 못한다. 새 문서는 묶음 없이(`개념/계류`) 만들 수 없다(화면 · MCP 모두 거절).
- 화면의 「묶음」 고르기 · 차례 · 그래프 · 찾기가 고른 묶음과 공유 묶음만 본다. 「모든 개념」은 모든 묶음을 묶음 · 본부(쓰거나 고친 사람의 소속) · 글자로 거른다(`GET /api/concepts`). API 는 `b=<묶음>` 으로 받고, 찾기는 `b` 가 없으면 위키 전체다.

| 종류 | 경로 | 무엇 |
|---|---|---|
| 개념 | `<묶음>/개념/<이름>` | 다른 문서에서 링크하면 마우스를 올릴 때 요약 카드가 뜬다. 요약은 본문 첫 문단(목록이면 첫 항목)이다 |
| 매뉴얼 | `<묶음>/매뉴얼/<권>/<이름>` | 권별로 차례에 모이고, 머리말 `order` 가 작을수록 앞이다 |
| 틀 | `<묶음>/틀/<이름>` | 다른 문서에 끼워 넣을 조각(주의 문구 · 공통 절차). 왼쪽 목록에는 나오지 않고 검색 · 그래프로 찾는다 |
| 일반 | `<묶음>/<이름>` | `<묶음>/대문` 이 그 묶음의 첫 화면이다. 없으면 공유 묶음의 대문 |

링크 `[[이름]]` 은 이렇게 찾는다(`pages.rs` `resolve`).

1. 전체 경로(`[[산사태/개념/유출구]]`)
2. `[[<묶음>/이름]]` — 앞 조각이 있는 묶음 이름이면 그 묶음에서
3. 링크를 쓴 문서의 묶음 → 공유 묶음(목록 차례)에서 제목 · 별칭 · 이름 · 묶음 안 경로(`[[개념/유출구]]` · `[[틀/주의]]`)
4. 다른 묶음 — 그 이름의 문서가 위키 전체에 하나뿐일 때만. 둘 이상이면 붉은 링크로 두고 묶음을 붙이게 한다

머리말은 `title` · `aliases`(목록) · `order` 만 쓴다.

제목 · 별칭 · 파일 이름은 같은 묶음 안에서 한 문서에만 쓴다. 저장할 때 다른 문서와 겹치면 서버가 거절한다(화면 · MCP 모두).
겹치면 `[[이름]]` 이 경고 없이 한쪽으로만 가기 때문이다. 다른 묶음과는 겹쳐도 된다. 이미 겹쳐 있던 문서는 새로 단 이름만 본다.

새 개념을 넣으면 옛 문서에 같은 말이 링크 없이 남는다. MCP `find_mentions`(명령줄 `mentions <경로>`)가 그 자리를 문서마다 첫 자리 하나로 찾아 주고,
MCP `write_page` 로 새 문서를 쓰면 응답의 `mentions` 에 같은 목록이 붙는다. 링크로 바꾸는 것은 쓰는 쪽이 골라서 한다 — 한국어는 낱말 끝을 가를 수 없어(「계류」 · 「계류보전」) 자동으로 이으면 틀린 링크가 생긴다.

```markdown
---
title: 유출구
aliases: [유출 지점]
---
```

### 위키 표기

마크다운(GFM) 위에 다섯을 더한다. 끼워 넣기 · 목차는 한 줄에 홀로 쓴다.

| 표기 | 뜻 |
|---|---|
| `[[제목]]` · `[[제목\|보일 글자]]` | 링크. 없는 문서는 붉게, 개념은 마우스를 올리면 요약 카드 |
| `![[틀/주의]]` · `![[계류#정의]]` | 끼워 넣기. 그 문서 · 그 절(제목 글자)을 이 자리에 그린다. 원문 링크가 붙고, 자기 자신 · 이미 끼운 문서는 다시 끼우지 않으며 3단계까지 들어간다 |
| `[목차]` | 이 자리에 이 문서의 `##` · `###` 차례를 그린다 |
| 언어를 `mermaid` 로 적은 코드 블록 | 글 도식(흐름 · 차례 · 관계). 처음 나올 때만 mermaid 를 받는다. `securityLevel: strict` · 밝은 · 어두운 화면에 따라 다시 그린다 · 글이 틀리면 원문과 오류를 보인다 (2026-11-11) |
| `![설명](/assets/<해시>.html "높이")` | 움직이는 도식. 격리된 틀(`iframe sandbox="allow-scripts"`)에 띄운다. 높이 기본 480, 틀 안 문서가 `{ type: 'wiki-anim-height', height }` 를 보내면 맞춘다 (2026-11-11) |

움직이는 도식(html)은 누구나 올리는 스크립트라 위키와 같은 출처로 돌리지 않는다 (`api.rs` `asset`).

- 서버가 html 자산을 `Content-Security-Policy: sandbox allow-scripts; … connect-src 'none'; frame-ancestors 'self'` 로 낸다. 주소창에서 바로 열어도 출처가 없는 문서라 위키 쿠키 · 저장소 · API 에 닿지 못하고, 밖으로 요청도 보내지 못한다.
- 화면의 틀에도 `allow-same-origin` 을 주지 않는다. 둘 중 하나만 풀려도 격리가 깨지므로 함께 고친다.
- 그래서 끼우는 html 은 글꼴 · 라이브러리 · 그림까지 한 파일에 담아야 한다. 만드는 규칙은 위키 「그림 표준 › 움직이는 도식」이 정본이다.
- 올리기 : 화면은 본문에 html 파일을 붙여 넣는다 · MCP `upload_image` 의 `format: "html"` · 명령줄 `image <파일>.html`.

### 자산 지우기 (2026-11-11)

그림 · 도식을 갈아 끼우면 옛 파일이 `assets/` 에 남는다(이름이 내용의 해시라 새 판은 새 이름이다). 쓰지 않는 것을 지우는 창구다.

- 목록 : `GET /api/assets/list`(로그인 없이) · MCP `list_assets`(`unused: true` 면 쓰는 문서가 없는 것만) · 명령줄 `assets [--unused]`. 칸 : `name` · `url` · `size` · `used_by`.
- 지우기 : `POST /api/assets/delete {name}`(로그인) · MCP `delete_asset` · 명령줄 `rm-asset <이름>`. 커밋 「자산 <이름> 지움」 하나가 남아 이력에서 되살릴 수 있다.
- 본문에 `/assets/<이름>` 을 쓰는 문서가 하나라도 있으면 409 로 거절하고 그 문서들을 알려 준다(`pages.rs` `asset_users`). 지우면 그 문서에 깨진 그림이 남기 때문이다.
- 이름만 받는다. 「../」 · 하위 폴더 · 점으로 시작하는 이름은 400 이다(`store.rs` `remove_asset`).
- 2026-11-11 처음 정리할 때 10개를 지웠다. 모두 한때 문서가 쓰다가 새 그림으로 갈아 끼운 옛 판이었다(`git log -S <이름> -- pages` 로 확인).

- 끼운 글은 검색 · 뜻 검색에서 **원래 문서에서만** 센다. 끼운 문서는 링크로 세어 역링크 · 그래프에 잡힌다.
- 차례는 넓은 화면(1280px 이상)에서 오른쪽에 붙고, 좁은 화면에서는 본문 위에 접어 둔다(`[목차]` 가 있으면 접는 차례는 그리지 않는다).
- 한국어의 `**범위(모양)**를` 처럼 문장부호 뒤 조사가 붙는 굵게 · 취소선은 `remark-cjk-friendly` 가 풀어 준다. 표준 CommonMark 로는 별표가 그대로 보인다.

### 책 보기 (`/book/<묶음>/<권>`)

매뉴얼 권 하나를 책처럼 읽는다. 왼쪽 차례의 권 이름 옆 책 단추 · 매뉴얼 문서 아래 「권을 책으로 이어 읽기」로 연다(`web/src/pages/Book.tsx`).

- 표지(권 이름 · 설명 · 장 수 · 마지막 고친 날) → 차례(장 아래 `##` 절까지) → 모든 장을 `order` 순서로 이어 붙인 본문. 넓은 화면에서는 오른쪽 차례가 지금 읽는 장 · 절을 따라간다.
- 같은 권 문서로 가는 `[[링크]]` 는 책 안의 장 앵커(`#c3`)로 바뀐다. 권 밖 문서 · 개념은 위키 주소 그대로다.
- 제목 id 앞에 장 번호(`c2-`)를 붙인다. 장마다 같은 이름의 절(「개요」)이 있어도 차례가 엉뚱한 장으로 가지 않는다.
- 「인쇄 · PDF 저장」은 브라우저 인쇄에 맡긴다(서버에서 PDF 를 만들지 않는다). 장마다 새 쪽에서 시작하고, 어두운 화면에서도 흰 바탕으로 찍힌다. 인쇄 직전에 늦게 받는 그림을 모두 받는다.
- 매뉴얼 문서의 이전 · 다음은 그 권 안에서만 넘긴다(2026-11-10 전에는 다른 권으로 넘어갔다).

2026-11-10 BookStack(권 첫 화면 = 표지 겸 차례) · mdBook(한 화면에 이어 붙이고 인쇄는 브라우저에) · Confluence · GitBook · DokuWiki · MediaWiki 의 권 단위 보기를 보고 정했다.


## 검색

두 검색의 결과를 순위 합치기(RRF)로 섞는다. 결과마다 `via`(keyword · semantic · both)와 뜻 검색의 `similarity` 가 붙는다.

- **낱말 검색** : tantivy · BM25. 한글 · 한자는 글자 하나와 이웃 두 글자로 쪼개 색인한다. 그래서 「유출구가」 · 「유출 구」로도 「유출구」를 찾는다. 찾을 말 토큰의 6할 넘게 겹쳐야 결과로 내고, 제목 · 별칭이 맞으면 더 얹는다.
- **뜻 검색** : 단락마다 EmbeddingGemma 로 벡터를 만든다. 질의와의 코사인 유사도가 기준(`WIKI_EMBED_MIN`)보다 높고 1등과 0.15 넘게 벌어지지 않은 것만 낸다. 「캠핑하다 물에 갇힘」처럼 문서에 없는 말로 물어도 가까운 단락을 찾는다. 저장하면 바뀐 단락만 다시 만들고, 만드는 동안에도 검색은 멈추지 않는다(4개씩 나눠 만든다).

문장으로 물으면 낱말 검색 쪽에 흔한 글자(「물」 · 「곳」)가 섞여 순위가 흐려질 수 있다.

### 단락과 근거 찾기 (RAG 기반)

문서는 `##` · `###` 제목에서 단락으로 나뉜다(긴 단락은 1,200자 안쪽으로 문단에서 다시 나눈다). 단락이 뜻 검색 · 근거 찾기의 단위다.
모델에는 `title: <권> › <문서 제목> (<별칭>) - <절> › <하위 절> | text: <본문>` 꼴로 넣는다 — 매뉴얼 권 이름까지 붙여 권이 여럿이어도 같은 이름의 절을 가른다.
위키 묶음은 넣지 않는다. 묶음은 찾기 범위로 거르고, 넣으면 문서를 옮길 때마다 단락 벡터를 모두 다시 만든다.
표는 줄마다 `머리칸: 값 · 머리칸: 값` 글로 펴서 넣는다(`|---|` 같은 기호가 섞이면 뜻 검색이 흐려진다).
단락마다 화면의 제목 앵커와 같은 id(github-slugger 규칙)를 붙여, 인용 주소가 `/w/산사태/개념/사방댐#관리` 처럼 그 단락으로 바로 간다.

- `GET /api/retrieve?q=<질문>&k=8&b=<묶음>` · MCP `retrieve`(`bundle`) : 묶음을 주면 그 묶음과 공유 묶음에서만, 질문에 맞는 단락을 낱말 · 뜻 검색으로 찾아 RRF 로 합쳐 준다. 칸 : `url` · `path` · `title` · `heading` · `text` · `via` · `similarity`.
- 답을 만드는 단계(LLM 호출)는 아직 없다. 붙일 때는 이 단락들을 모델에 문서 블록으로 넘기고 인용을 켠다 — 답의 문장마다 `url` 이 근거로 달린다.
- 단락 나누기 규칙을 바꾸면 다음에 켤 때 단락 벡터를 모두 다시 만든다(문서 20장 · 단락 91개에 22초, 2026-11-09).

## 설정 (환경변수)

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `WIKI_HOST` | `127.0.0.1` | 다른 PC 에서 들어오게 하려면 `0.0.0.0` |
| `WIKI_PORT` | `4500` | |
| `WIKI_DATA` | `./data` | 문서 · 계정을 둘 폴더 |
| `WIKI_ROOT` | 실행한 폴더 | `web/dist` 를 찾는 자리 |
| `WIKI_NAME` | `Seesun Wiki` | 화면 위에 보일 이름 |
| `WIKI_PUBLIC_URL` | 요청 주소 | MCP 연결 안내에 찍힐 주소. 역방향 프록시 뒤면 바깥 주소를 넣는다 |
| `WIKI_EMBED` | `gemma-q4` | 뜻 검색 모델. `gemma`(원판 · 메모리 약 1GB 더) · `off`(낱말 검색만) |
| `WIKI_EMBED_MIN` | `0.35` | 뜻 검색 결과로 낼 최소 유사도 |
| `WIKI_MODELS` | `<WIKI_DATA>/models` | 모델을 둘 폴더. Windows 는 이 뒤로 약 140자가 붙어 260자를 넘으면 모델을 열지 못하므로, 깊은 폴더에 둘 때 짧은 경로를 준다 |

사이트는 도메인 맨 앞(`/`)에 두어야 한다. 하위 경로(`/wiki/`)에는 아직 맞추지 않았다.

## NAS 로 옮기기

```bash
docker build -t company-wiki .
docker run -d --name wiki -p 4500:4500 -v /volume1/docker/wiki:/data -e WIKI_NAME="Seesun Wiki" company-wiki
```

지금 PC 의 `data/` 를 NAS 의 `/volume1/docker/wiki` 로 복사하면 문서 · 이력 · 계정이 그대로 간다. 사내망 밖으로 열 때는 NAS 의 역방향 프록시로 HTTPS 를 씌운다. 로그인 쿠키는 HTTPS 로 들어오면 Secure 로 붙는다.

메모리는 뜻 검색을 켜면 약 210MB, 끄면(`WIKI_EMBED=off`) 약 13MB 다(문서 18장 · Windows 실측 2026-11-09). 이미지는 x86-64 debian 기준이다 — ARM NAS 는 onnxruntime 판을 따로 맞춰야 하므로 `WIKI_EMBED=off` 로 쓰거나 `cargo build --release --no-default-features` 로 뜻 검색을 빼고 만든다.

## MCP

로그인 › 내 계정에서 토큰을 만들면 연결 명령이 나온다.

```bash
claude mcp add --transport http wiki http://<주소>:4500/mcp --header "Authorization: Bearer <토큰>"
```

도구 : `search` · `retrieve` · `list_pages` · `read_page` · `write_page` · `page_history` · `read_revision` · `recent_changes` · `upload_image`(그림 · html 도식) · `list_assets` · `delete_asset` · `style_guide` · `check_page` · `find_mentions`.
`write_page` 는 이미 있는 문서를 고칠 때 `read_page` 로 받은 `commit` 을 `base_commit` 으로 요구한다. 그 사이 사람이 고쳤으면 저장하지 않는다.
커밋 작성자는 토큰 주인의 해시이고 메시지 끝에 `(MCP)` 가 붙는다.

### 명령줄

MCP 를 등록하지 않은 곳에서는 `npm run wiki -- <명령>` 이 같은 도구를 부른다. 고친 기록은 MCP 와 똑같이 남는다.

```bash
npm run wiki -- login <계정>        # 서버 PC 에서 토큰을 만들어 ~/.wiki/config.json 에 둔다
npm run wiki -- search 유출구
npm run wiki -- retrieve 사방댐에 흙이 차면 어떻게 하나   # 근거 단락과 인용 주소
npm run wiki -- read 계류 --out 계류.md
npm run wiki -- check 산사태/개념/계류 --file 계류.md          # 저장하지 않고 글쓰기 표준 검사
npm run wiki -- write 산사태/개념/계류 --file 계류.md --base <commit> -m "바꾼 것"
npm run wiki -- guide writing                         # 글쓰기 표준 (image : 그림 표준)
npm run wiki -- image 그림.jpg
npm run wiki -- assets --unused                       # 아무 문서도 쓰지 않는 자산
npm run wiki -- rm-asset 43f8f3138ef1bc8b.html        # 자산 지우기 (쓰는 문서가 있으면 거절)
```

다른 PC 에서는 화면에서 받은 토큰으로 `login --token <토큰> --url http://<주소>:4500`.

## 계정 · 고친 사람 표시

가입할 때 이름을 받지 않는다. 아이디 · 비밀번호와 소속(목록에서 고름)만 받는다.
화면 · 이력 · git 커밋에는 계정마다 하나인 **해시 6자**만 보인다 — 선임이 쓴 글을 후임이 고칠 때 눈치 보지 않도록 고친 사람을 드러내지 않는다.

- 해시는 서명 키(`data/secret`)로 아이디를 HMAC 한 앞 6자다. 아이디를 알아도 키 없이는 해시를 셈할 수 없다. 키를 지우면 해시가 모두 바뀐다(지난 이력의 해시는 그대로).
- 아이디 · 소속은 본인(내 계정)과 관리자(관리 화면)만 본다. 소속은 내 계정에서 바꾼다.
- 2026-11-09 이전 커밋에는 그때의 이름이 작성자로 남아 있다. 이력을 고쳐 쓰지 않는다.
